Sistemas · 02

Arquitectura desacoplada

Un sistema desacoplado organiza la aplicación en componentes con responsabilidades y ciclos de vida propios. En su forma más conocida, la interfaz de usuario y la lógica de negocio residen en aplicaciones separadas, coordinadas mediante contratos explícitos en vez de depender de una implementación interna compartida.

Dos capas. Un contrato claro.

El frontend presenta la información, gestiona la interacción y consume capacidades. El backend aplica reglas de negocio, valida operaciones, protege los datos y ofrece servicios. La API define qué puede solicitar cada cliente y qué respuesta puede esperar; ese límite reduce el conocimiento mutuo y permite evolucionar cada lado con menor impacto.

Comunicación

REST para recursos; WebSockets para tiempo real

Con REST, el cliente envía solicitudes HTTP a recursos y recibe respuestas, habitualmente en JSON. Es un modelo sencillo de cachear, depurar y escalar. Cuando se necesita comunicación persistente y bidireccional, como en notificaciones o colaboración en vivo, WebSockets permiten intercambiar mensajes sin abrir una nueva solicitud por cada evento. En ambos casos, versiones, autenticación, validación y manejo de errores forman parte del contrato de integración.

01 / ESCALA

Escalabilidad horizontal independiente

Frontend y backend pueden escalar según sus propias cargas. Se pueden servir activos estáticos desde una CDN y añadir instancias de API cuando crece el tráfico de negocio, sin replicar todo el sistema de forma indiscriminada.

02 / ELECCIÓN

Flexibilidad tecnológica

El cliente y el servidor pueden usar frameworks, lenguajes y ritmos de actualización distintos. Mientras mantengan el contrato acordado, el equipo puede sustituir una implementación sin reescribir necesariamente la otra.

03 / ENTREGA

Despliegues continuos y zero-downtime

Los componentes pueden publicarse por separado mediante estrategias como despliegues graduales o blue-green. La disponibilidad global se conserva si las versiones siguen siendo compatibles y la infraestructura permite retirar instancias sin cortar el servicio.

04 / RESILIENCIA

Tolerancia a fallos aislados

Los límites entre servicios ayudan a contener ciertos errores: una falla de interfaz no detiene automáticamente los procesos del servidor. Timeouts, reintentos controlados, circuit breakers y degradación elegante complementan esa separación; el desacoplamiento por sí solo no garantiza resiliencia.
